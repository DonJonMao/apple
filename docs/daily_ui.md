# 日常查看与训练记录界面

2026-11-19 的界面合同以日常使用为主。首页显示数据更新概况、运动与力量训练次数，并可直接进入力量记录或心率页面；不默认展示原始数据库目录、同步游标或 JSON。导入和存储配置收在侧栏，导入结果用新增、重复、更新及未完成数量说明。概况中的日期来自实际记录，不用导入时间冒充观察时间。

营养暂不提供界面入口，知识库不作为日常展示工作区。既有数据、检索权限和后台能力保留，不删除用户记录或修改资料审核状态。当前启用 10 个工作区。

## 身体记录

- 心率 / HRV：分别显示静息心率与 SDNN 的逐日表格和趋势图，列为日期、指标、数值、单位、来源。继续消费原规范指标，不把普通心率当静息心率，也不把 SDNN 当 RMSSD。
- 睡眠：默认只显示日期、观察时长和可读来源。零、负数、未知及非有限时长不进入本页有效记录表和平均值；不同来源分别统计，不补齐缺失日。没有有效睡眠记录不能确定未佩戴设备，原始记录及科学指标仍保留原语义。
- 体重：显示逐日称重表和趋势。当前窗口无数据时，另列截止时点可见的最近有效历史称重，明确其真实日期和窗口外参考身份，并提供扩大范围按钮。历史参考不填入当前窗口指标，不当作今日体重；更正、删除、移动时间及原始单位仍经既有可见修订选择与归一化处理。

表格不默认显示内部 ID、series label、来源键元组等字段。可读来源重名时仍区分记录条件，不能为了简化名称合并不同来源。窗口、时区、实际截止时刻和计数保留；计算说明放在次要展开区。

## 运动

按周、月、年汇总，可选择年份及日期范围。按实际开始时刻归入所选时区的日历日期，周从周一开始，跨年使用 ISO 周年。汇总同时列出次数、已有时长、已有设备能量及缺项数；明细保留开始时间、类型、分钟、kcal 和设备来源。

能量优先使用 Workout 总能量字段。该字段没有可用值时，仅回退到起止时刻与整场完全相符、有效且唯一的活动能量统计；相同重复统计只用一次，冲突、分段及未知单位不相加造值。kJ 使用既有单位换算；不再叠加 health_sample 活动能量。缺失保留未知，真实记录的 0 保留 0；已记录能量不等于真实代谢或全天总消耗。部分周期和疑似重复保留明确说明。

## 力量训练

主区顺序是新增训练、当前训练、选动作、添加组、保存实际记录、结束训练。无需先建模板，可以先选部位或直接搜索动作。按实际情况确认重量口径，不明确时保留未知；器械、侧别等更多条件放入展开区。模板、动作维护、历史和离线工具位于次要管理区域。

每组实际记录位于建议和管理控件之前。实际重量、次数、RIR 和计划均不伪造默认值；RIR 可以未知，不需要参考组身份或采纳反馈。原建议权限、分组身份、更正、历史冻结及可选整场反馈语义不变。两个结束入口共用同一服务，主区结束也保留用户已填的可选反馈并校验时长。

## 验证入口

所有公开测试均使用隔离合成数据，真实身体数据和运行回执保留在忽略的本地目录。

- `tests/integration/test_workspace_switching.py`：完整 app 的 10 个可见工作区、中文身体表格、首页直接进入力量、隐藏营养与知识库、写锁下首页读取、声明失效提示及无关全套分析不执行。
- `tests/unit/test_body_pages.py`：来源可读性、睡眠有效分母、无 Plotly 时仍有表格、历史称重参考与扩大范围。
- `tests/integration/test_weight_history_reference.py`：历史可见性、原始单位、时间分页边界和修订/删除不复活。
- `tests/integration/test_workout_workspace.py`：日历与时区、时长/能量缺失和零、单位、整场统计回退及写锁下只读浏览。
- `tests/integration/test_training_entrypoint_ui.py`：真实服务贯穿无模板开始、选动作、创建空白组、记录实际及结束，原参考身份与反馈表保持为空。
