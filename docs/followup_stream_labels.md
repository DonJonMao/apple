# R07：相同来源与设备的协议标签

压力夹具暴露了显示碰撞：两个静息心率组的来源和设备相同，但协议分别已记录与未知，期间中位数分别为62.5和61.0。原统计与冻结身份一直分组保存；报告摘要只显示来源/设备，趋势选择只显示来源，用户无法辨认两条不同记录。

`analytics/health_context.py::stream_labels`现在统一生成显示名。单组保持来源/设备的简短名称；同指标的名称碰撞时，补出实际协议、来源版本及冻结日值中明确记录的采样、姿势等条件，缺项仍写未记录。`context:`只说明有部分条件记录，不升级为完整协议。结构化条件转换成中文，不把长JSON或内部hash放入普通标题。

如果不同的不透明协议或未映射条件仍显示相同文字，追加绑定原`stream_id`和`protocol`的稳定短别名，明确“独立记录组、不表示条件已确认相同”。别名不依赖数组顺序；完整原协议、分组身份和事实身份保留在“本组冻结身份与条件”详情，不合并、删除或挑选其中一组。

摘要与下载正文使用同一组显示名。新`report-reading-view-2`将显示名冻结在各stream中，页面趋势选择优先读取该冻结名。新报告版本为`joint-period-report-3.0.2`，使报告缓存与新文字有独立身份；科学计算版本和原值未改。旧报告仍读取原Markdown与对象；旧对象没有显示名时，趋势导航仅从其冻结字段产生可读标签，并明确历史正文保持原文，不查询当前健康记录补身份。

受影响代码为`health_context.py`、`ui/health_comparison.py`、`ui/review_page.py`、`workflows/report_objects.py`及`workflows/period_report.py`。新增独立测试`tests/integration/test_followup_stream_labels.py`涵盖同日同值不同协议/版本、已知部分条件与未知条件、单组简洁显示、同日不透明协议及未映射字段的稳定别名、趋势选择的真实冻结组、版本失效与旧字节保留。

页面驱动`tools/followup_stream_browser.py`使用另一个日期和值夹具：26条合成记录、13天、每天相同时间、同来源/设备但两个协议状态。它将先在独立子进程用实际冻结r5源码生成3.0.1旧报告，再由当前应用真实生成3.0.2、下载、选择两组并核对图中本期值，查看390/1440宽度和第一条完整发现；从历史入口分别重开新旧报告，检查旧下载、存储行及全部既有内容对象原字节。外部网络拦截，健康库完全合成。

版本缓存测试是在同一当前实现内临时切换版本字段，用于验证失效与已有对象保护；它不是实际运行r5源码的证明。实际旧格式兼容另由上述子进程与浏览器回执证明，两种证据分开。
