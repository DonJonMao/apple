# 按已审核指标绑定限定检索候选

检索版本 `metric-hybrid-1.5.5` 增加显式 `candidate_scope="reviewed_metric"`。它用于已有计算指标的来源依据：先取得当前有权处理的领域候选，再依照已审核的指标绑定及显式前提依赖，形成完整证据组的候选集合。随后在该集合内执行词项、语义、RRF和精排，仍受原前20候选、K和完整结构单元预算约束。

该设计处理的是宽泛同领域阅读材料挤出已审核指标依据的问题。例如VO₂原实跑中的直接测量比较原文dense第1、融合第36，没有锚点进入前20，导致两组已有审核证据均未选中。修复不写入指标、来源、主张或Gold的特殊ID，不改变RRF常数或扩大预算；集合由当前精确审核关系确定。结果只代表这些明确绑定的来源依据，不声明检索了全部潜在相关科学文献。

## 入口与兼容

```python
response = workbench.explain_metric(
    metric_id, analysis_task, computed_metric_result, context, release_id,
    mode="hybrid_rerank", candidate_scope="reviewed_metric",
)
```

`retrieve_for_metric`同样接受这一参数。API省略参数时继续使用 `all`，保持原全部领域资料路径和默认查询ID；显式范围使用独立查询ID，并审计候选范围版本、领域候选数、排除背景数及完整组定位。它与固定查询语言形式相互独立，不将个人数值、备注或上下文插入查询。

实际分析页的“依据范围”默认选择“已审核的指标依据”，另可选择“同领域资料（含待审核阅读材料）”。后者允许查阅背景，但待审核材料不授来源解释权。CLI的声明JSON可以设置 `candidate_scope`；原命令及检索方式保持兼容。

新冻结发布固定 `candidate_scope_version=reviewed-metric-candidates-1.5.0`。历史发布没有该字段时，原 `all` 路径仍可读取；显式使用新范围会拒绝，不能静默改写历史解释依据。变更范围语义版本后，固定该版本的新发布也拒绝漂移。私人schema、原77项配置、Source/Theory两库和原文均无需迁移。

## 权限和完整性

候选范围复用现有逐主张内容审核、逐指标应用审核、精确Span哈希、领域审核、来源权利/当前状态、冻结成员和适用条件检查。前提仅沿显式 `required_by` 边闭合；未知适用性、缺前提、撤销或循环均不能形成完整组。缺少完整指标绑定时返回 `no_complete_reviewed_metric_group`，不调用公共模型，也不自动退回未审核背景来授权解释。

相关冲突仍从全部合格主张检查，即使冲突另一端没有进入限定候选或最终K。最终输出继续重查来源、主张和依赖的当前状态；模型不能覆盖这些门禁。完整组超过K时保持证据不足，不截断组后冒称覆盖。必要领域、证据类型或上下文仍缺少时同样不授权解释。

该范围不创建SourceClaim、ApplicationRule或科学参数，不改变已有审核范围和数值候选权限。来源说明不能证明设备准确、当前个人测量有效、诊断、阶段或训练处方。

## 验证与后续验收

针对性合成检查覆盖背景超过20项时的组选择、K不足、无绑定时不调用模型、公共请求仅含固定查询及限定证据、未知条件、provisional领域、撤销、前提、未选中冲突以及新旧冻结身份。整仓回归和真实公共模型集成另有哈希回执，不能用软件通过代替知识准确率。

VO₂/周期实跑属于已知开发缺口的回放，新增独立案例数为0。原三形式144次冻结评测使用另一语料副本和未改动的1.5.4实现，原分数保留；不能把本修复回填成那些测试通过。后续仍需新的排名不可见案例、完整答案语义裁决及独立来源家族评测。四本目标教材正文及独立专家/真人科学验证缺口继续保留。
