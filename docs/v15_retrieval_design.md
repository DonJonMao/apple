# v1.5 检索设计（开发中）

`MetricResult + AnalysisTask → 固定指标依赖 → 当前权限/许可/版本/条件 → lexical 与 dense → RRF → 有界聊天精排 → 逐主张证据与冲突/完整性核对`。

`metric-hybrid-1.5.3` 将原77项之外的两个 [来源观测扩展](v15_source_observations.md) 接到同一入口。原注册表和领域配置默认仍77项；扩展采用独立版本的固定任务/领域/证据类型要求，并在含绑定的冻结发布中单独固定配置哈希。来源VO₂字段与月经原始类别不因检索而成为生理真值、周期阶段或处方，生产审核缺项继续返回证据不足。

词项排序保留现有分词方法，按可复核词项频次与文档频率排序。新路径没有删去旧 `query()` 或改写历史 lexical baseline；当前尚未声称新词项排序与历史评分逐字等价。RRF 固定常数为 60，精排候选上限 20；这是产品资源配置，非生理阈值，不通过留出集反复调权。

Embedding 是实际可用的 `qwen3-embedding-8b` OpenAI-compatible 服务，观测向量维度 4096。文档和查询用途分开；查询使用固定指令。索引缓存按服务/模型身份、部署 epoch、输入哈希和用途区分，显式构建、增量复用；普通查询不会重新嵌入整本教材。同身份出现不同维度即拒绝。未配置稳定部署 epoch 时，仅同进程复用，不能把未核验权重当作固定模型修订。

显式索引默认单个请求，可用 `build-vectors --batch-size 16 --workers 4` 设置最多4个在途请求。SQLite 读写及进度回调仍在调用线程执行，失败后保留已提交批次并可续建。历史空表格明确记为 `empty_structured_unit`，不删除其原文。默认以3500 UTF-8字节保守准入；可显式配置同源 `/tokenize` 和经实测的 `context_window_tokens`，对较长的完整原文按实际token数准入，并显式禁止输入截断。超过实际token上限、计数不完整、服务容量与声明不一致或分词服务不可用时明确排除/失败，不裁切原文。

准入不会改变模型、原始Embedding输入或缓存键，已有向量不重算。较长输入的精确计数在索引进程内按完整输入哈希复用；已缓存文档直接复用向量。普通检索不调用分词服务处理整本教材。分词请求沿用公共资料联网同意、原文资格和同源凭据边界；配置默认关闭该能力。本次实际4096-token服务下，原21个字节超限单元中18个完整原文可准入，3个表格确实超出容量。

`metric-hybrid-1.5.2` 对超限JATS表格增加不可变的结构索引投影：保留同级子表作用域、标题、表头/脚注、显式headers引用和不可分的rowspan行组，并记录原Span、原文/结构哈希及精确行列位置。所有子向量完整可用时，以最大子向量相似度给原Span一个dense名次，返回完整原文并记录获胜位置；部分索引不参与排名并明确降级。投影不创建新Span、主张或审核，查询不重建文档索引。具体合同见 [结构表格索引](v15_structural_table_indexing.md)。

用户提供的精排端点实际是 `deepseek-v4-flash` chat/completions，适配器身份为 `chat_listwise`，不是专用 cross-encoder。它只能返回现有 ID 的严格排列；未知、重复、缺失 ID、截断或错误 JSON 都会降级。不能修改来源、许可、适用性、主张内容或候选权限。

精排每次输入上限为24000 UTF-8字节。`metric-hybrid-1.5.1` 使用从尾向前的重叠窗口，每窗保留完整结构单元、约半窗重叠；每个能单独装入预算的融合候选都会提交，最终保留全部候选 ID 的排列。单个超预算单元保持原位置，明确列入 `unranked_ids` 并标记降级；不截断原文。每窗发送前复查当前资格，联网期间撤回会阻止后续窗口提交。审计记录各窗候选 ID、成功排列、失败尝试和未精排项，中途失败也保留前面窗口的审计并退回原融合顺序；窗口结果不代表整个候选集获得一次全局联合排序。原先只发送前缀并丢掉尾部的实现及其烟测/评测结果保持历史身份，不回写成绩。

最终证据在同一 K 个片段预算内按完整已审核主张分配。一个组必须有直接证据进入本次候选池，才能沿精确的审核链接补齐其余片段；不能从未召回的主张直接制造命中。先选补充缺失必要证据类型或领域的组，再按最佳直接片段名次排序，不叠加模型分数或生理权重。显式 `required_by` 主张依赖递归核对；依赖缺失、撤销、循环或依赖适用性未知不能形成有效解释，只有已知不适用的条件边可以跳过。依赖主张的范围及限制随解释投影传递，不能只保留主结论。组放不进剩余预算时不放宽完整性条件。词项、语义、融合和精排各组实验采用相同选择规则，补入的依赖片段不冒称被精排；原始阶段名次与组选择审计分别保存。

两项服务的实际权重 revision 都没有得到可验证证明。部署 epoch 是操作者控制的缓存失效边界，不能替代真实模型版本证明。配置模板见 `docs/examples/model-services.v15.json`；凭据只在被忽略的本地配置或环境变量中。

外发内容仅为固定指标任务和已通过权限检查的公开片段投影。个人数值、备注、用户 ID 和适用上下文不拼入 Embedding/Reranker 查询。AI 结果解释的联网同意另行控制，仍沿用原字段投影和逐字事实核验。

权限、当前来源状态、撤回、更正 epoch、解析修订及冻结成员在排名前检查。被拒绝主张的已拥有片段不能从 raw-document 路径重新进入。NC 文档只能在明确的本地非商业用途使用；图注及识别出的第三方材料待审。

模型返回后再次检查入选来源、主张和阅读上下文的当前可用性，防止联网排序期间发生撤回后仍授予权限。候选初筛使用 SQL 排除被替代解析和无关领域；读取候选ID后释放游标，避免在长期模型调用期间占用 SQLite 读锁。片段读取省略整本书的大型解析报告，保留全部定位和权限字段。

精排后仍须命中逐片段已核对的领域、经审核的主张—指标绑定、全部必要证据类型和适用信息，才可给 source_explanation；candidate 永远由既有规则服务决定。显式冲突在显示预算之前检查。没有实现原文自动矛盾识别，不能把“未发现显式冲突”解释为文献没有冲突。

冻结索引保存片段、领域审核、主张、关系及配置哈希，并在存在结构投影时记录其集合身份。旧发布缺少投影集合时按空集合解释，不能自动获得后来新增的子索引。后加领域审核或应用绑定不进入冻结成员；来源撤回、主张撤销及当前冲突通知仍可阻止当前使用。原冻结记录不重写。

章节/段落/表格/公式上下文按结构解析。父级相邻片段仅是阅读背景，先通过同一候选资格检查，不会自动变成额外主张。无可读文本、边框缺失的表格、多页表格、公式符号、印刷页码和版面顺序仍需人工核对；没有悄悄运行 OCR。

每次检索（含拒绝）保存独立 audit_id，记录公开 ID、配置、模型、排除理由和各阶段名次；不保存原始个人健康上下文。模型缺失、错误或索引不完整明确标记 retrieval_degraded；不能把退回词项排序称为完整混合检索。

评测运行身份现在同时固定知识模块与领域配置的文件哈希；代码改变后不能混用旧输出续跑。评测工具默认声明 `development_replay`，已暴露的 Gold 不会因为重新运行而恢复独立身份。旧冻结结果与历史留出不变。

## 显式查询形式

检索1.5.4可明确选择 `zh`、`en` 或 `zh_synonym`，来自独立静态登记，不接受私人自由查询插值；省略时原组合查询不变。形式、语言、登记版本/哈希和固定输入哈希进入审计及新查询ID。新发布固定登记哈希，旧发布不会隐式采用新增形式。评测按同一Gold和预算分别运行，报告表达×领域、语言和跨领域的实际分母；多种表达仍是同一知识案例的相关重复。具体合同、原冻结兼容及运行命令见 [固定查询形式](v15_fixed_query_forms.md)。
