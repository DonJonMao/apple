# v1.5 检索设计（开发中）

`MetricResult + AnalysisTask → 固定指标依赖 → 当前权限/许可/版本/条件 → lexical 与 dense → RRF → 有界聊天精排 → 逐主张证据与冲突/完整性核对`。

词项排序保留现有分词方法，按可复核词项频次与文档频率排序。新路径没有删去旧 `query()` 或改写历史 lexical baseline；当前尚未声称新词项排序与历史评分逐字等价。RRF 固定常数为 60，精排候选上限 20；这是产品资源配置，非生理阈值，不通过留出集反复调权。

Embedding 是实际可用的 `qwen3-embedding-8b` OpenAI-compatible 服务，观测向量维度 4096。文档和查询用途分开；查询使用固定指令。索引缓存按服务/模型身份、部署 epoch、输入哈希和用途区分，显式构建、增量复用；普通查询不会重新嵌入整本教材。同身份出现不同维度即拒绝。未配置稳定部署 epoch 时，仅同进程复用，不能把未核验权重当作固定模型修订。

显式索引默认单个请求，可用 `build-vectors --batch-size 16 --workers 4` 设置最多4个在途请求。SQLite 读写及进度回调仍在调用线程执行，失败后保留已提交批次并可续建。历史空表格明确记为 `empty_structured_unit`，不删除其原文；超过3500 UTF-8字节的完整结构单元单独报告，不能静默截断以迁就模型。

用户提供的精排端点实际是 `deepseek-v4-flash` chat/completions，适配器身份为 `chat_listwise`，不是专用 cross-encoder。它只能返回现有 ID 的严格排列；未知、重复、缺失 ID、截断或错误 JSON 都会降级。不能修改来源、许可、适用性、主张内容或候选权限。

精排实际输入上限为24000 UTF-8字节。先取融合候选的完整片段前缀，审计记录真正提交数量及预算排除项；不会把未提交的候选冒称已精排。第二次真实烟测实际提交并精排7项，首次烟测因预算超限精排0项的记录继续保留。

两项服务的实际权重 revision 都没有得到可验证证明。部署 epoch 是操作者控制的缓存失效边界，不能替代真实模型版本证明。配置模板见 `docs/examples/model-services.v15.json`；凭据只在被忽略的本地配置或环境变量中。

外发内容仅为固定指标任务和已通过权限检查的公开片段投影。个人数值、备注、用户 ID 和适用上下文不拼入 Embedding/Reranker 查询。AI 结果解释的联网同意另行控制，仍沿用原字段投影和逐字事实核验。

权限、当前来源状态、撤回、更正 epoch、解析修订及冻结成员在排名前检查。被拒绝主张的已拥有片段不能从 raw-document 路径重新进入。NC 文档只能在明确的本地非商业用途使用；图注及识别出的第三方材料待审。

模型返回后再次检查入选来源、主张和阅读上下文的当前可用性，防止联网排序期间发生撤回后仍授予权限。候选初筛使用 SQL 排除被替代解析和无关领域；读取候选ID后释放游标，避免在长期模型调用期间占用 SQLite 读锁。片段读取省略整本书的大型解析报告，保留全部定位和权限字段。

精排后仍须命中逐片段已核对的领域、经审核的主张—指标绑定、全部必要证据类型和适用信息，才可给 source_explanation；candidate 永远由既有规则服务决定。显式冲突在显示预算之前检查。没有实现原文自动矛盾识别，不能把“未发现显式冲突”解释为文献没有冲突。

冻结索引保存片段、领域审核、主张、关系及配置哈希。后加领域审核或应用绑定不进入冻结成员；来源撤回、主张撤销及当前冲突通知仍可阻止当前使用。原冻结记录不重写。

章节/段落/表格/公式上下文按结构解析。父级相邻片段仅是阅读背景，先通过同一候选资格检查，不会自动变成额外主张。无可读文本、边框缺失的表格、多页表格、公式符号、印刷页码和版面顺序仍需人工核对；没有悄悄运行 OCR。

每次检索（含拒绝）保存独立 audit_id，记录公开 ID、配置、模型、排除理由和各阶段名次；不保存原始个人健康上下文。模型缺失、错误或索引不完整明确标记 retrieval_degraded；不能把退回词项排序称为完整混合检索。
