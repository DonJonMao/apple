# 产品改版性能与数据口径验收

2026-11-20。本页只报告隔离合成数据库的实测。浏览器端到端、首屏和交互可用时间由浏览器验收独立记录；下述 Python/SQLite 成绩不等于手机或线上页面成绩。

## 环境与方法

- Linux 5.15、aarch64、Python 3.11.7、SQLite 3.41.2；系统暴露 192 个逻辑 CPU，ARM implementer `0x48`、part `0xd01`。脚本单进程执行，无专属 CPU 隔离。
- 系统 `MemTotal=2109313276 KiB`，约 1.96 TiB；这是共享宿主机可见内存，不表示测试占用了这些内存。测试数据库位于同机临时目录，SQLite WAL；不调用模型，不进行网络请求。
- 两个量级分别为 100,000 与 1,000,000 条健康样本，每库另有 100 场 × 100 组、共 10,000 个真实服务事件支持的完成组。训练事实不是直接伪造一张聚合表。
- 健康样本跨度 365 天。混合比例：普通心率 50%、步数 30%、活动能量 19%、睡眠片段 0.6%、静息心率/SDNN/体重/VO₂max 各 0.1%。时间用交错分布，避免某一类型全部集中在窗口外。这里特意区分高频普通心率与稀疏静息心率；科学分析仍计算其真实所需的全部有效样本。
- 基线从 `351822c` 单独归档 Python 源码执行，随后对同一合成数据库升级后测改版代码。没有合并旧草稿 PR；复用并重新验证其类型候选索引思路与时态反例。
- **冷计算**：进程和数据库已启动，清空有界结果缓存，操作系统文件缓存不清空，每量级 5 次。**热访问**：相同进程、页面、显式截止、已提交数据版本连续 30 次。报告 P50 和 nearest-rank P95；5 次冷测试的 P95 是该组最大值，不能代表稳定的大样本尾延迟估计。
- 首次 Python 进程启动、数据库迁移、日常冷计算分别记录。下述数据库字节数包含源样本、修订台账、1 万训练组及事件历史，已做 WAL checkpoint。合成建库速度不是导入产品吞吐量验收。

## 索引、迁移与兼容

|健康样本|升级前 DB 大小|升级后 DB 大小|本次增量升级开库耗时|
|---|---:|---:|---:|
|10 万|375,738,368 B|381,575,168 B|657.56 ms|
|100 万|1,829,912,576 B|1,888,997,376 B|6289.06 ms|

`REPOSITORY_MIGRATION_REVISION=3`，时态查询投影 `4.5`。从已有 `4.3`/`4.4` 投影只追加类型/日期/记录身份索引和缓存领域修订触发器，不重建来源台账、不改写原始 payload。升级在原 Repository 显式事务中完成；就绪连接只读检查标记，不重复重建索引。百万库第一次升级约 6.29 秒，属于启动升级，不计入日常 3 秒页面目标。之后示例暖开库约 2.7–3.0 ms。用户无需清库或重新导入。

`source_revision_type_window(table_name, canonical_type, event_end, event_start, record_id)` 先缩小候选记录身份，再解析截止时点最新可见修订，最后核对类型、真实事件时间和删除状态。不能把候选旧版本直接当最终值。精确微秒边界在 Python/已注册时间函数内核对，SQLite Julian 日期只作候选索引。

领域触发器随来源修订更新，包含同一记录曾使用的类型，因而“心率更正为其他类型”也使心率缓存失效。更正日期、删除、撤销、可见时间修订以及其他进程导入都更新持久版本；动作目录和无关健康类型编辑不会重算心率。没有在浏览时写派生分析。

普通库修订身份继续用于完整分析，页面事实按依赖领域细化。事实缓存最多 16 项，300 秒安全过期；键包含工作区文件身份、相关已提交修订、页面、范围/显式截止、来源筛选、时区与算法版本。自动窗口按用户时区日期更新，不含当前分钟。相同键并发请求合并计算；等待方使用自己的 SQLite 连接，不跨线程共享连接。调用方尚未提交的视图不进入进程共享缓存。

可选复盘仍用原全量科学入口，但 `v13.analyze` 和 `core.all_analysis` 的自动缓存也已去掉分钟键，采用本地日期与 300 秒 TTL；全量结果继续依赖完整输入/知识修订。命中显示原真实计算截止，TTL 后再计算随时间变化的窗口。显式历史 as-of 使用精确截止，不随自动时钟过期。

规范单位转换版本升为 `healthzip-units-1.4.1`，仅新增 VO₂ 等价写法 `mL/(kg*min)`；保留原始单位、数值和转换依据，旧冻结结果不回写。科学指标公式、来源审核与既有双重进阶规则未改变。性能探测后补齐了这个转换版本字符串；数值处理逻辑相同，随后单位转换、来源观察与查询计划 19 项定向补验通过，完整隔离测试副本包含最终版本字符串。

## 口径与行为证据

同一详情只有一个主要半开窗口：本周为用户时区周一零点起，本月为月初起，近 30 天为今天及此前 29 个本地日期至实际截止。卡、图、明细、解释读取同一 `workspace_scope`。月初/周初恰好零点时没有 MetricResult，不借用上一日数据。体重与有氧独立，范围外 VO₂ 只作为有日期的历史参考。来源/设备/协议分开，SDNN 不变为 RMSSD，缺失不填零。

固定科学指标 `STATE-SLEEP-24H` 仍按过去 24 小时计算，不能在周初/月初被页面日历窗口截短。它的额外依赖窗口在 `workspace_scope.extra_metric_windows` 明确列出；依据折叠区和使用它的解释标为“过去24小时（独立于所选范围）”。周/月主卡、睡眠逐日图和本期最近观测日期仍只使用页面窗口。周初/月初 01:00 的合成反例验证：前一日睡眠的 420 分钟属于固定 24 小时结果，但不会变成本期逐日均值或本期观测。

总览上一周期比较使用相同已过本地时长；前月更短时在前月结束处截断，并给出实际边界。“已完成训练”必须整场已结束且所选范围有实际完成组；工作组只计明确 `set_type=work` 的完成事实。空训练、草稿、冲突和已删除记录不计入。历史参考与当前事实分开。

后端专项执行 68 项通过，覆盖以下可复核文件（完整项目结果由交付文档另列）：

- [产品数据合同](../../tests/integration/test_product_data_contract.py)：外进程导入、独立写锁、只读初次浏览、跨类型/日期/删除/恢复/可见时间、工作区与来源隔离、时区月界、旧 VO₂、单点与空范围、缓存容量机制相关并发、旧体重来源筛选、同期比较。
- [类型候选查询](../../tests/integration/test_typed_source_queries.py)：加入 5000 条无关样本后 SQLite 指令数不随之增长；类型/日期/删除/恢复与微秒可见边界；已有投影升级不重写台账字节。
- [详情规范指标一致性](../../tests/integration/test_workspace_analysis_scope.py)、[摘要与日历范围](../../tests/integration/test_workspace_calendar_summary.py)、[开库并发](../../tests/integration/test_repository_open_concurrency.py)、[来源观察科学合同](../../tests/science/test_source_observations.py)、[单位转换](../../tests/unit/test_normalize.py)。

睡眠额外窗口修正后的当前源码补验：产品数据合同、详情规范指标一致性、摘要与日历范围共 47 项通过，包含月初/周初两例 `test_sleep_fixed_24h_dependency_does_not_change_page_calendar_facts`；对应源码与测试 Ruff 通过。该补验晚于完整隔离测试副本创建，单独记录，避免把旧副本成绩视为这次修改的证明。

全量入口自动缓存修正后的当前源码补验：产品数据合同、全量查询/缓存规划、睡眠选择草稿共 33 项通过，Ruff 通过。两入口分别验证跨分钟保留原截止、TTL/相关修订/本地日期失效，另验证显式 as-of 不随自动时钟过期。睡眠草稿测试按模拟的真实经过时间推进 TTL 时钟，持续验证范围离开、周期变化、修订与用户选择生命周期。

复跑：`tools/benchmark_product_data.py` 生成或复用隔离合成库；`tools/profile_product_path.py` 使用 `--code-root` 分别分析归档基线和当前源码；`tools/product_performance_scenarios.py` 执行首次进程、跨页、跨分钟、持锁和另进程导入场景。所有 JSON 工件只有合成规模、计数、环境及计时；数据库不进入仓库。

## 浏览器性能

使用 Chromium 158.0.8127.18、1440×1000 视口、同机 HTTP/WebSocket，仍为上述共享宿主机和隔离合成库。每库已有 1 万训练组；生命周期测试在主后端基准之后追加过一行，因此浏览器库实际分别为 100,001 / 1,000,001 条健康样本，381,587,456 / 1,889,009,664 B。测试阻止站外请求，无模型调用。浏览器量级基准没有同方法的改前采样，不据后端加速比例推算整页加速比例。

工具 [product_page_benchmark.py](../../tools/product_page_benchmark.py) 记录四个阶段：第一个事实卡、事实卡及主趋势、当前渲染完成且 Streamlit 忙碌状态消失、页面函数服务端计时。首开从 `page.goto` 前开始；页内导航从浏览器实际捕获的 DOM click 开始，另保留自动化命令发出至完成的时间，包含 Playwright 等待按钮可操作的开销。新范围的冷访问先确认新的渲染身份，避免把旧图/卡当新结果；该项事实/趋势时间是确认新快照已可见的保守上界。

每量级热访问 30 次，操作为“心率 → 体重 → 心率”，只计返回心率；下表为 P50 / P95。原始逐次证据：[10 万](../../artifacts/product_redesign/browser-performance-100k.json)、[100 万](../../artifacts/product_redesign/browser-performance-1m.json)。

服务/驱动准备单列，发生在首次导航计时之前；JSON 的 `service_ready_ms` 包含测试浏览器驱动上下文启动。每库新进程首开只有 1 次，运行中冷范围只有 2 次，均报告逐次值，不称为冷访问 P95。两个运行中冷范围的已测值都低于 3 秒；新进程首次整页导航仍需约 3.7–3.9 秒，不能宣称所有首开都已低于 3 秒。初始化和日常访问分别保留，首次成本没有隐藏进加载成功状态。

首次 HTTP 文档响应约 3.90 ms，两库 DOMContentLoaded 分别为 410.20 / 418.90 ms。之后使用复用 WebSocket，当前计时无法单独分离纯网络。逐样本“完整交互减服务端页面计时”的残差 P50 / P95 分别为 323.21 / 428.96 ms、253.93 / 317.33 ms，包含 WebSocket 传输、队列、计时范围外的服务端工作、序列化和浏览器处理/绘制；首开约 3.4–3.6 秒也处在页面函数计时之外。不能把这些残差全部归因网络或前端绘制。

保留的 [前次 10 万自动化起点回执](../../artifacts/product_redesign/browser-performance-100k-automation-timing.json) 有 30 次样本，事实/趋势 P95 为 832.49 ms，完整交互 P95 为 837.11 ms，服务端 P95 为 136.58 ms，按当次定义超过 800 ms。该轮未记录实际 DOM click，无法事后把慢样本精确拆成按钮等待、排队或绘制；不能仅凭后续成绩将其归咎于自动化工具。之后明确分离两种计时起点并重新记录全部 30 次，未丢弃这份慢样本，也没有把不同定义的两轮合并计算 P95。

本页证明同机 Chromium 的实测结果和边界。真实 iPhone Safari、软键盘、安全区及移动网络时延未测；浏览器手机尺寸截图也不等于这些项目已通过。
