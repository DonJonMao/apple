# HealthZIP v1.4 使用手册

## v1.4 新增操作

动作目录现在支持完整wger快照、中文名称/别名、分类、详情和本地图片/视频。上游中文、历史中文名和AI译稿会分别标记；肌群标签只是目录信息。没有示范、下载失败、许可待核分别展示，不用相似动作图片替代。升级保留原46动作、历史动作版本、模板和私人别名。

在「力量」页开始训练，或明确选择要恢复的未结束训练。页面当前展示哪场，新增动作与组就属于哪场。选择动作后填写本台器械、负荷口径、侧别、动作幅度和结构化参考协议；执行前指定参考组。目标与实际分别填写，不能把目标自动当成完成记录。

在动作下展开「本次候选与后续复核」：

1. 按需填写「建议适用信息」中的年龄、目标、训练经验和健康范围。这些只在本机保存，是自报信息，可留未知。
2. 选择当前组目标和本次策略，输入本台器械真实可用档位，点击「核对候选依据并保存」。页面会保存具体任务或缺项。
3. 已达到用户次数上沿时可核对双重进阶；未达到上沿仍可主动选择负荷/次数试验。次数进阶使用你明确的较高次数目标，不默认加一次。数值来源是实际记录、用户目标和器械档位。
4. 选择采纳、暂缓或不采纳。修改后采用会另存一个任务，保留原任务；它不会自动改写模板。
5. 正常记录实际执行。结束训练后，在「历史 / 冲突」找到该场，选择实际组并补录已执行、部分执行或未执行及原因。任务达成只说明记录满足目标，不证明策略导致长期进步。

当前症状、疼痛、技术限制或关键质量未知会阻止升级任务。候选生成后出现新事实或来源撤回，页面提示重新核对，原冻结依据仍可查看。没有适用正文规则时显示具体缺项。已核对核心规则使用AI辅助内容核对策略，不能理解为专家为你开具处方。

计划组完成率和负荷、次数、余力目标匹配率分别显示，缺目标与缺实际单列，不合成为一个总分。清空组时间不会清除已经记录的疼痛或技术限制；时间缺项需要复核。记录“至少还有3次余力”会保留为区间，同时填写RPE也不会把它改成精确次数。

在「力量」页勾选「查看表现分析与复盘」查看各动作、条件、负荷层的独立描述，再按需生成周/月报告。不同负荷不会被拼成一条能力趋势。停滞标签仍需要实际误差、等效范围、查看预算和适用校准；没有标签不影响记录和描述。

分析顶部的「选择历史任务与体重参考」可以明确选择参考组及同日体重。它显示实录完整外部负荷/体重，以及相同条件、协议和负荷的最近历史次数与余力；不自动选体重、不承诺下一次完成，也不等于测得1RM或已校准个人预测。

动作列表分页展示中文名、器械、身体部位和本地缩略图，点击条目后查看详情。主页面和离线页都区分上游译名、沿用历史名称与尚未人工核对的AI译稿，保存、重启和导出独立页面后仍保留标记。无示范、尚未下载、下载失败、许可待核和已撤回分别显示。断网前在离线记录器缓存完整动作/模板及需要的媒体。离线待同步事件仍需导出备份，浏览器清理存储可能删除尚未同步的数据。

2026-11-12 01:06:09 UTC冻结的完整离线目录包含1004个动作、389张图片和78个视频，已核实来源快照中的全部媒体均已下载并纳入完整包；默认本机安装与包中媒体一致。视频保留来源编码，HEVC等格式需要兼容浏览器或播放器；若页面无法播放，可用兼容播放器打开完整包内的原文件。已验证的H.264播放不代表所有视频格式均兼容。

知识问答会列出已回答与尚缺依据的部分。当前知识发布1.4.11可解释不显著与等效的区别、TOST及对应区间、等效界值依据和研究设计限制；也可解释成人活动范围、肌力活动低起点、相对活动增量、年龄/体能/经验因素与力竭定义。进阶选项区分负荷、训练量、训练频次、动作选择和持续时间，不表示所有变量必须同时增加，也不保证个人结果。

HHS第7章多数安全建议适用于所有年龄，但特定年龄和健康状况另有指导；第4章成人活动建议仍限于18–64岁。复合问题分别核对两个章节，不能混用范围。增加活动后新出现关节痛等症状应咨询健康服务提供者；先前无症状不能覆盖新症状，页面不诊断病因或给出固定减量比例。

N1解释HC与HAC的误差条件、HC0–3的小样本讨论、滞后权重、预白化及有限样本修正的区别；这些设置不保证任意短序列或反复查看都有效。M2解释TOST须两侧均通过，单侧α设为0.05时对应双侧90%区间；这是条件示例，不替你选择参数。区间一端超出等效界值不能宣布等效，也不自动证明重要差异。其独立正态平行组示例不能直接认证个人训练时序。M2与N1属于研究补充，在“来源分区”保留`research`时才会使用；只选择`core`时不会使用。页面不执行个人模型、选择个人核或带宽、给出误判率或提供个人校准。

指定教材版次、章节、附录或表格时，只有对应正文可作为回答依据；仅有主文提及附件不代表已取得附件。继续核对需要取得可合法处理的相应正文，并确认书目身份和原文定位；其他资料不能冒充它的内容或页码。上述解释不能确定个人最优训练数字、个人等效结论或固定进阶幅度，也不增加训练候选权限。四本付费教材的授权正文尚未取得；两份中国指南也仍待明确的重用许可，相关问题继续显示具体缺口；不需要因此停止记录和其他已有依据的功能。

全量ZIP仍按流导入，已有历史不删减或抽样。自动页面分析可在60秒内复用相同版本结果，修改记录、导入数据或切换时区会使相应缓存失效；请以显示的截止时间为准。旧库自动事务升级至schema v4，先备份；恢复时写入新路径，不覆盖唯一原库。

## 这份工具解决什么问题

HealthZIP 是一个完全在电脑本地运行的 Apple Health 数据整理和分析工具。它把 iPhone「健康」导出的 ZIP 作为第一次历史回填，再用 Health Auto Export 向电脑发送每日新增数据。数据写入本地 SQLite，网页界面显示数据质量、趋势、训练和报告。没有手表或没有健康ZIP，也可以直接记录训练。

工具不会接入 HealthKit，不需要账号，不把原始健康数据上传到云端，也没有自有 iOS App。当前最适合的使用方式是：Mac 开机时运行接收器，iPhone 和 Mac 在同一可信 Wi-Fi，Health Auto Export 按日 POST 到 Mac。

## 先记住三个命令

在项目根目录打开终端，第一次运行：

```text
./healthzip setup
```

导入第一次从 iPhone 导出的完整 ZIP：

```text
./healthzip import /path/to/AppleHealthExport.zip
```

以后每天让手机自动推送，并打开分析界面：

```text
./healthzip start
```

`start` 会同时启动 REST 接收器和 Streamlit 网页界面，并自动打开电脑上的网页。REST 默认监听可信局域网，网页默认只监听本机；若要让 iPhone Safari 也打开网页，使用 `./healthzip start --lan`。按 `Ctrl-C` 会停止这两个进程。电脑必须开机且该命令正在运行，Health Auto Export 才能送达数据。只在电脑本机使用时，可以执行 `./healthzip start --local`，此时手机不能访问。

Windows 没有执行权限时，在 PowerShell 使用 `py healthzip setup`、`py healthzip import <ZIP路径>` 和 `py healthzip start`。这里的 `<ZIP路径>` 代表实际路径，不要把尖括号一起输入。

## 第一次安装和导入

### 1. 准备

需要 Python 3.9 或更高版本，以及一个项目目录。不要把真实 ZIP、SQLite 数据库、原始同步 JSON 或个人 CSV 放进 Git 仓库。仓库里自带的 ZIP 和 CSV 都是合成测试数据。

### 2. 一键安装

```text
./healthzip setup
```

该命令会：

- 创建或检查 `.venv`；
- 安装项目、lxml、Streamlit 和 Plotly；
- 创建 `.local`；
- 生成 `.local/sync_token`，并尽量设置为仅当前用户可读；
- 保存默认设置到 `.local/healthzip.json`。

默认位置如下：

| 内容 | 默认位置 |
| --- | --- |
| SQLite 数据库 | `.local/healthzip.sqlite3` |
| REST 原始请求备份 | `.local/inbox/` |
| 文件夹同步目录 | `.local/phone-sync/` |
| 同步 token | `.local/sync_token` |
| 本地报告 | `reports/latest.md` |
| REST 端口 | `8765` |
| 网页端口 | `8501` |

### 3. 导入第一次完整 ZIP

在 iPhone「健康」App 中导出完整健康数据 ZIP，把它放在电脑上，然后执行：

```text
./healthzip import /Users/你的名字/Downloads/export.zip
```

入口会自动做三件事：检查 ZIP 结构、流式导入 `export.xml`、显示数据盘点。它不会把整个 XML 一次性读入内存，也不会要求手动解压。相同 ZIP 再导入会根据 SHA-256 跳过；不同快照中的重叠记录会按 fingerprint 去重。

如果第一次没有导入周期数据，之后明确需要周期字段时，使用高级命令：

```text
python -m healthzip.cli --db-path .local/healthzip.sqlite3 \
  import-apple /path/to/export.zip --include-cycle --recheck
```

### 4. 生成第一份报告

```text
./healthzip report
```

报告写入 `reports/latest.md`。报告中的每个结论都带有时间窗口、样本数、质量状态、来源和限制；数据不足时会说明缺什么，不会把空白当作零。

## iPhone 每日增量推送（推荐）

### 电脑端启动服务

在项目根目录执行：

```text
./healthzip start
```

终端会显示 REST 健康检查地址、网页地址和 token 文件位置。默认 REST 监听 `0.0.0.0:8765`，网页监听 `127.0.0.1:8501`；需要手机打开网页时才使用 `--lan`。REST 只用于可信局域网，不要做路由器端口转发，不要把它暴露到公网。

如果只想单独启动 REST 接收器：

```text
./healthzip serve
```

### 确认 Mac 的局域网 IP

Wi-Fi 通常使用：

```text
ipconfig getifaddr en0
```

如果没有输出，再试 `ipconfig getifaddr en1`，或在「系统设置 → 网络 → Wi-Fi」查看 IP。假设 IP 是 `192.168.1.23`，REST 地址就是：

```text
http://192.168.1.23:8765
```

在 Mac 浏览器先打开 `http://192.168.1.23:8765/health`。看到 `{"status":"ok"}` 才继续配置手机。若浏览器也打不开，先检查 `./healthzip start` 是否还在运行以及 Mac 防火墙是否允许 Python 接收局域网连接。

### 在 Health Auto Export 中配置

Health Auto Export 的菜单名称可能随版本变化，找「自动化」「REST API」「自定义请求」或同类入口，配置：

| 设置 | 填写内容 |
| --- | --- |
| 方法 | `POST` |
| URL | `http://Mac局域网IP:8765/v1/ingest/health-auto-export` |
| Header 名 | `X-HealthZip-Token` |
| Header 值 | `./healthzip token` 输出的完整 token |
| 可选 Header | `X-HealthZip-Source: health_auto_export` |

不要把 token 写进公开截图、仓库或报告。iPhone 与 Mac 必须连接同一个 Wi-Fi。先在 Health Auto Export 中发送一次测试请求，再用 `./healthzip status` 查看最近批次。

心率和 HRV-SDNN 要选择「逐样本」或足够高粒度的导出。不要只选择每日 Min/Avg/Max 汇总来冒充原始样本；系统会把这种批次标为 `aggregate_not_raw`，不会用它生成原始心率趋势。Workout 可以按应用支持的标准结构一起发送。

### 每日运行时发生什么

REST 接收器先把原始 JSON 保存到 `.local/inbox/`，再在 SQLite 事务中导入。每条记录优先使用 Health Auto Export 的上游 ID；没有 ID 时使用逻辑 fingerprint。

`./healthzip status` 的批次统计含义：

| 计数 | 含义 |
| --- | --- |
| `new` | 第一次写入的记录 |
| `duplicate` | 已存在且内容没有变化，安全跳过 |
| `updated` | 同一逻辑记录内容改变，旧版本保留为 `superseded` |
| `deleted` | 上游明确要求删除，记录标记为 `deleted` |
| `invalid` | 格式、单位或粒度不符合要求；其他有效记录仍可提交 |

分析默认只使用 `active` 记录。因此手机每天只推送当天或最近窗口的数据，也不会因为重复推送而重复计数。Mac 休眠、关机、换 Wi-Fi 或 REST 服务停止期间，手机端可能显示发送失败；恢复后让 Health Auto Export 补发最近窗口即可。

## 网页界面和手机力量记录

运行 `./healthzip start` 后，在 Mac 打开 `http://127.0.0.1:8501`。如果要用同一 Wi-Fi 的 iPhone Safari 记录力量训练，先停止服务，再执行 `./healthzip start --lan`，然后打开 `http://Mac局域网IP:8501`。

力量页可直接开始临时训练，也可创建、复制或修改自选模板。搜索动作后，确认器械实例、侧别、动作幅度、设置与负荷口径；不清楚的内容保留未知，仍可以正常记录。

### 胸部计划示例

1. 在模板区创建「胸部计划」，搜索「上斜史密斯卧推」。登记所用器械，选择「单边片重」，确认两侧对称及动作条件；不知道有效杆重时留空。
2. 填自己的目标次数与RIR，保存模板后开始训练。目标是计划，当前完成组数仍为0。
3. 每组填写30kg、10次、RIR2，选择停止原因。要用于后续参考比较，在完成前明确标记参考组。点击完成才计入实际。
4. 填整场反馈后结束。整场sRPE与组RPE单独记录；缺时长协议或整场sRPE时不计算该内部负荷。
5. 下次开始同模板，带入上次值后仍为草稿。填32.5kg、8次并完成，界面应显示两侧配重合计增加5kg；不知道杆重时不显示虚构含杆总重。
6. 在「本次候选与后续复核」输入器械实际可用重量。缺可比参考、明确计划或审核依据时，查看具体缺项；不能把身体信号自动转成减重百分比。
7. 记录采纳/未采纳、实际执行和原因，再查看本周或本月复盘。完成次数不等于候选成功；重量口径、努力程度、质量与冻结任务也必须一致。

### 参考协议、可选试验与结束后反馈

在「结构化参考测量协议」中明确填写协议标识、版本、参考组选择规则、用力终止规则、动作节奏和参考组前休息规则。未知字段留空；自由文字备注不能代替这些条件。改变测量规则时使用新版本。每个动作、器械条件和协议形成独立任务，不把卧推与深蹲或不同协议合并为同一个趋势。

在「本次候选与后续复核」选择本次依据的组目标，再选择候选策略并填写本台器械实际可用档位。双重进阶核对计划上沿；更难档位、降低次数的可选试验允许未达到上沿时主动选择，但仍需完整参考协议、明确目标与适用审核依据。页面会冻结所选组目标版本、原计划、策略和当时依据。

选择「讨论组数试验」或「讨论训练间隔试验」后，可填写「本次可用训练时间（分钟，可留空）」，再点击「核对候选依据并保存」。有适用的正文解释依据时，页面列出一般原则及引用、明确计划的工作组、本次已记录组、同条件历史场次与间隔，以及需要你判断的问题。未记录场次不等于休息日；讨论不能确定个人最佳组数、恢复间隔或数值处方。讨论选择和反馈可保存、重开查看，不能把讨论改写为未经核对的数值任务。疼痛或技术限制仍须先复核；来源撤回后新讨论停用相应解释，原冻结依据保留。

需要后续观察时，在保存候选前展开「可选：预先约定后续观察窗口」，勾选启用并填写含时区的起点、终点；终点不计入窗口。这是你的观察计划，不是系统指定的恢复时间。未约定时只复核本次执行。

缺少适用审核依据时保存缺项，并继续记录；已撤回或待复核规则不能生成新的数值候选。选择采纳后按正常组记录实际执行，执行前指定参考组。结束训练后，进入「历史 / 冲突」选择这场训练，在「本次训练的建议与结束后反馈」填写采纳、执行状态、实际组和结果。复核会核对候选之后的参考组、重量、次数、RIR及质量；修改历史后重新核对当前事实，冻结依据仍保留。完成任务不证明试验导致进步。

在分析的「复盘与个体学习」或「本周 / 本月复盘」查看冻结目标与实际值、单位和负荷口径、相对目标上下界的差值及质量缺项。预先约定的窗口内，只比较后续场次中条件、协议和负荷一致的有效参考组；显示执行参考、后续记录及次数/RIR等观察差值。尚未到窗口、未执行、执行未确认、没有可比记录、资料不可用会分别说明。跨周/月的观察计划可在与窗口重叠的复盘中出现，已观察的变化不表示策略造成了变化。

### 编辑、恢复与离线

实际字段会保存为草稿。暖身/工作/测试与递减、超级组关系分别记录；等长动作填时长，负重行走填距离，不伪造次数。失败尝试和跳过与完成分开。历史可以修改、删除和撤销，修订会保留并使旧分析失效。冲突时看双方值后明确选择，不能用后到的编辑静默覆盖。

暂停后可以继续原会话；下一场创建新的会话，同一天也保留两场。休息计时支持暂停、继续、延长和跳过。由相邻实际开始/结束时间派生的休息与主动记录的休息分开保存；修订时间会重算受影响组，缺少端点时显示未知。当前与历史页面同时编辑同一组时，过期编辑会提示冲突，未修改的缓存字段不会覆盖新记录。

断网前下载力量页的独立HTML，并先连接本机接收器缓存动作和模板。打开本地HTML即可离线记录，刷新后保留草稿与待同步事件。联网后同步；同一事件丢失响应后重试不会重复写入，两组真实相同的数据有不同组ID。可导出浏览器备份；清除浏览器站点数据或换浏览器会影响未同步资料。

旧CSV仍可导入：

```text
python -m healthzip.cli --db-path .local/healthzip.sqlite3 import-strength templates/strength_sets_template.csv
```

旧记录没有负荷口径时显示unknown，不自动认为等于含杆总重。v1.3交换格式与命令见 `docs/training_v1.3.md`。

## 分析、来源与不确定性

六类分析包括可比力量表现、每日候选、停滞及试验、身体状态、能量背景和复盘/个体学习。每个结果可展开窗口、截止时间、输入记录ID、算法/参数版本、计数分母、限制和区间类型。日历周/月只使用截止前已发生且当时已知的资料；当前周期未结束时标为partial。

### 选择历史任务与体重参考

1. 展开分析顶部的「选择历史任务与体重参考」，在「历史参考组」中明确选一条记录。列表只含当前窗口中截止前已知、事先指定且协议和质量可用的参考组；这同时确定要重复的动作、器械条件、协议和负荷，不填写未来实际次数。
2. 如需负荷/体重比，在「同日体重记录」选择来源，核对后勾选确认。日期按当前分析时区判断；系统不会自动采用最近体重或混合不同秤。同日是时间对齐规则，不证明测量条件相同。没有适合的体重可留空，仅查看历史参考。
3. 点击「计算并保存所选参考」，查看结果和来源，也可「下载所选参考完整结果」。B0使用相同条件、协议及归一化负荷的最近历史次数与余力，可能晚于你选择的那条旧记录；它是历史基线，不是个人预测保证。来源日期、单位换算和记录ID随结果保留。
4. 负荷/体重只在完整外部负荷及有效体重均可确认时显示，以kg/kg计。单边片重缺杆重、器械刻度或每只哑铃质量不会自动变成完整负荷；缺项保持未知。该比值使用所选实录负荷，不是实测1RM。e1RM须另有明确公式与适用域，公式研究代理值不能包装成已验证能力。

改变参考组会清空体重选择和确认；改变选择或数据后，旧结果不再作为当前结果展示，需重新计算。保存的历史分析仍保留当时选择和截止时间。

睡眠不包含inBed，缺失不补零；主睡眠需有明确片段和归属日期，不能把多晚累计当作一晚主睡眠。SDNN不换算RMSSD。能量窗口累计以kcal表示，日均单列有效日分母；静息和活动能量先按相同日期及来源配对，缺项不拼成完整总能量。体重按原始来源分开，不混合不同秤。设备能量不是实测TEE；只有体重变化和手表能量无法唯一识别绝对摄入。三次记录可显示序列，但不足以证明停滞、个人预测或训练处方有效。没有校准时仍能记录、看事实，并获得具体缺项。

「专业知识」只查询本地取得且获准使用的资料，显示逐主张引用位置及来源/理论状态。首次可以运行 `python -m healthzip.knowledge seed`；获取公开资料用 `python -m healthzip.knowledge acquire --fulltext`。此命令不会读取或上传私人训练库。不可访问的来源有单独原因和重试入口；本轮已取得范围与限制见 [v1.4知识说明](v14_knowledge.md)，既有命令说明见 `docs/knowledge_v1.3.md`。

同一句包含多个问题时，页面分别列出有依据和未回答的部分，并区分力量、增肌和公共健康目标。可以在「明确问题目标」中选择并确认本次只查的目标，或指定来源、版次和章节；其他文献不能替代指定材料。展示条数没有包含全部所需依据时，结果仍是部分回答。来源正文不足、个人精确处方和完整个人计划不会由通用解释补出。

ACSM 2026综述的纳入标准是健康成人接受至少6周抗阻训练的随机试验综述；6周是来源研究范围，不是给你的训练时长处方。多周群体证据不能证明昨天加一组导致今天1RM提高，也不给以后每次的成功概率。换器械时，保留器械、动作与测试条件，在新任务中取得同条件的可比观察；特异性和负荷次数关系不提供两台器械的个人公斤换算或完成保证。这是来源范围的有界应用解释，不是已建立个人校准。

AI解释默认关闭。先配置自己的AI端点、模型和密钥，再明确选择发送结构化证据。任何数值、单位、窗口、摘要或引用校验失败时使用本地模板；无AI仍可使用记录、分析与报告。

## 文件夹同步备用方式

如果手机导出器只能把 JSON/JSONL 写入电脑目录，可以把文件放到 `.local/phone-sync/`，然后执行：

```text
./healthzip sync
```

也可以指定目录：

```text
./healthzip sync /path/to/phone-sync
```

JSON 文件按内容 hash 判断是否改变；JSONL 文件保存上次读取位置，追加数据、重启和离线补传都只处理新增完整行。文件被截断或轮替时会从头扫描，并用逻辑 key 去重。文件夹同步和 REST 接收是两种独立入口，选一种即可。

## 查看状态、质量和报告

日常只需：

```text
./healthzip status
./healthzip report
```

需要更细的质量窗口时，使用高级 CLI：

```text
python -m healthzip.cli --db-path .local/healthzip.sqlite3 inventory
python -m healthzip.cli --db-path .local/healthzip.sqlite3 quality --window-days 30
```

Streamlit 页面包括导入与总览、数据质量、心率/HRV、睡眠、运动、体重/有氧、力量、营养、周期和报告。AI 解释是可选项；默认不联网，只有明确勾选并配置服务时才会发送结构化 Evidence Cards，不发送原始 ZIP/XML。

## 常见问题排查

| 现象 | 处理方法 |
| --- | --- |
| 手机返回 401 | 在 Mac 执行 `./healthzip token`，重新复制完整 token；不要每次手动生成新 token |
| 手机返回 404 | URL 必须是 `/v1/ingest/health-auto-export`，不要漏掉路径 |
| Mac 浏览器打不开 `/health` | 重新执行 `./healthzip start`，确认端口 8765 未被其他程序占用 |
| Mac 能打开，iPhone 打不开 | 确认同一 Wi-Fi、使用 Mac 局域网 IP、没有访客网络隔离，检查防火墙 |
| 每天没有新数据 | Mac 必须开机并运行 `start`；iOS 后台自动化不是严格实时，可在 HAE 中手动补发 |
| 批次显示 `aggregate_not_raw` | 在 HAE 选择逐样本/高粒度心率和 HRV，而不是每日 Min/Avg/Max |
| `invalid` 或 `partial_failed` | 在 `status` 的最近批次错误中查看具体字段；有效记录仍会保留 |
| 页面打不开 | 确认网页端口 8501 未被占用；手机访问前先用 `./healthzip start --lan`，再使用 `http://MacIP:8501` |
| 想换电脑 | 先用下方backup命令取得一致备份，再在新电脑restore到新路径；如需重放，另存 `.local/inbox/` |
| 不知道环境是否正确 | 执行 `./healthzip doctor`，它会检查 Python、虚拟环境、lxml、Streamlit、数据库和局域网 IP |

## 备份、隐私和删除

升级前或定期执行在线备份，包含已提交WAL，不要在运行中仅复制主数据库文件：

```text
python -m healthzip.cli --db-path .local/healthzip.sqlite3 backup .local/backups/before-v13.sqlite3
python -m healthzip.cli restore .local/backups/before-v13.sqlite3 .local/restored.sqlite3
```

目标必须是不存在的新路径，防止覆盖原库。恢复后在网页侧栏选择新路径检查记录。v1/v2会在打开时事务升级到v3；失败回滚，可修正问题后重跑；更高版本会拒绝降级。升级保留既有组/会话ID及未知口径，不用当前时间伪造旧记录在过去已可见。

如果希望重放原始接收内容，一起备份 `.local/inbox/`。公开知识数据库、原文及审核版本保存在 `.local/knowledge/`，需要独立备份。私人数据库、CSV、报告和日志已被gitignore，不应提交。

默认服务只在可信局域网工作。不要把 8765 或 8501 做公网端口转发，不要把 token 分享给他人。HealthZIP 不会根据缺失记录断言「没有睡眠」「没有佩戴」或「没有吃饭」，报告也不是医疗诊断。

当前版本没有原生 iOS companion App、严格实时的 iOS 后台推送、macOS launchd 自动常驻或 Windows 计划任务。电脑关机或睡眠时，REST 无法接收；需要可靠的长期运行时，可以把 `./healthzip start` 加入你自己的登录启动项，但仍应保留 token 和防火墙保护。
