## 使用与正常路径

更新分析会按动作、物理条件和协议自动复核所选周期。分析页的「按问题分析」提供力量进阶、训练负荷与恢复背景、心肺观察、长期趋势与可能因素、体重与设备能量背景。六个结果页签分别显示事实、可比性、因素、下一步、依据和后来怎样。

长期趋势选择「同条件训练表现」后，可在该任务下选择已开始的训练，核对原有候选策略；已结束的训练仍可反馈。普通力量页练前候选、CLI、周/月报告均使用 `workflows.run_workflow`，候选创建前冻结共用复核的引用，行动计算继续由既有 STR-25/26 和审核规则服务执行。没有因果方法或严格 STR-22 校准，不阻断事实复核和独立合格的行动规则。

每项数值候选显示以下不同来源：

- 策略：实际当前可用的 ApplicationRule/理论版本、主张和原文定位、适用条件与限制。
- 个人记录：参考组 UUID、修订、日期、实际负荷/次数/RIR/质量/停止原因、所选目标版本与动作条件。
- 重量：用户确认的实际档位；同负荷次数策略沿用实录负荷。下一档不能自行授权数值建议。
- 次数：沿用计划上限或下限时如实标记；用户修改另有版本，不称资料推算的个人最优次数。
- RIR：用户明确目标；缺失保持未指定，不从睡眠或心率数据推算。

采纳、执行和目标达成分别保存。预先约定的随访窗口继续调用原 STR-27/28 和 REPORT-RECOMMENDATION-FOLLOWUP；未执行/未反馈时任务达成未知。完成一次目标不证明建议有效或造成肌肥大。

## 长期未改善的确定性定义

比较窗口在运行前固定，起点是该窗口内每个任务首条可见、预指定且可比的参考组。每条后续记录分别比较规范化负荷、次数和 RIR；助力档位采用实际难度方向，已记录的 RIR 区间参与有界比较。没有把三个分量加成分数。

若后续记录各分量均未超过起点，则显示「所选周期内记录未改善」并启动长期复核。RIR 不完整但负荷/次数未增加时，启动受限复核并保留努力程度未知。增重降次数等取舍不强行判优；已有更重负荷或更高 RIR 的明确改善，不会被旧负荷的重复记录掩盖。固定负荷序列另列。比较需要起点与后续数据是差值定义，不是新增次数/天数的生理停滞阈值。

复核检查任务条件、进阶机会、原计划执行、同场条件，以及每条参考所在训练开始之前的睡眠、RHR、SDNN、体重和可用自评。中间训练也参与，不能只比较首尾而漏掉中间变化。每日量使用同来源/设备/协议的实际记录，日期与距训练的关系保留；重复沿用一个旧观测不能证明状态稳定。睡眠时长差只称已观察睡眠差，完整性仍未知。

因素分列支持、削弱/反证和未知。来源解释只使用该指标当前匹配的完整审核证据组，保留主张版本、原文 hash、kind、位置、适用范围及明确冲突。来源的测量/方法说明不能被升级为个人原因。资料缺失、条件不匹配、服务失败与没有行动权限分别报告。

周/月对照使用前两个完整本地日历周期，本期未结束部分单列；新候选和反馈不能混入前期完成率。报告和下载携带同一复核结果及建议依据；明确选择的来源、时间范围和前瞻/回顾身份继续传递。

## 周期报告性能

静态指标定义按代码版本缓存，并对外复制，避免一份报告重复读取近两千次注册表。已审核检索在读取无关正文前，以当前合格主张引用作必要条件预过滤；完整组、前提、全体相关冲突、许可及当前使用检查不变。扫描内复用相同来源/组件许可，其他连接撤回或本连接写入均失效。审计明确标记当前主张引用的计数域；旧全领域候选分母不回写。

隔离合成反例覆盖组件权限不同、扫描中撤回及返回对象污染；实际资料库对照见 `retrieval-prefilter-equivalence.json`。性能测量只是本机单次记录，不代表 P95 或用户设备保证。
