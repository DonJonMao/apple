## 接口与持久化

五个入口分别为力量进阶、训练负荷与恢复背景、心肺观察、长期趋势与可能因素、体重与设备能量背景。沿用 strength/recovery/cardiorespiratory/longitudinal/metabolic 任务标识。旧冻结指标配置不改标题哈希，产品显示采用独立名称映射。

`WorkflowRequest` 只接受本地任务、时间、窗口及已保存声明的引用，不接受客户端计算结果、主张、批准状态或任意科学上下文。实际 MetricResult 由 Repository 和现有分析服务生成；计算时钟只从幂等身份中排除，冻结原结果不改写。

schema 5 在原库增加 workflow_run、workflow_context_revision、workflow_use_check 和 recommendation_request；运行引用 analysis_run，行动继续引用 training_recommendation/feedback。上下文只保存用户声明及需要的记录选择，不将自报或非空协议字符串当作专业验证。S0–S6 节点采用 true/false/unknown，分支独立保留。

相同候选请求的实际来源 UUID/修订、选中目标、器械条件/档位、策略、适用自报版本和权限共同构成 request_hash。墙钟和全库版本不是新意图。最终写入在 SQLite BEGIN IMMEDIATE 中重新核对，并原子保存候选与唯一请求映射；不同真实组仍有不同 UUID。计算前后发生相关更改须重新核对。候选记录的是现在的创建时点，不将历史分析日期倒记为建议日期。

历史目标、动作定义和条件从截止前 training_event 重放。已知未来执行时间的计划对象可以用于目标展示，但执行观察仍由原 history_as_of 的事件/可见时间双重过滤。当前候选与历史解释采用不同入口和身份。

上述结果不等于全库无误用；须在新节点消费时核对具体用途、完整组和当前生命周期。阅读相关性不授予权限。无需以本轮低相关标注撤销整篇来源或重写既有发布；完整追踪与针对性测试见本轮交付回执。

|输入或参数|身份/来源|允许用途|缺失行为|
|---|---|---|---|
