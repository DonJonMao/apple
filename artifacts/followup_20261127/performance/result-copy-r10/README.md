# 最终复制边界与解码遍历

从 r8 的原 100k 完整报告续修。r8 未达 15 秒冷生成目标，其 119.034989 秒结果保留；本目录只记录单阶段诊断，不能代替完整生成或浏览器计时。

## 最终实现

`isolated_copy` 只快速复制精确内建 dict/list/标量图，保留内部共享和循环。遇到 tuple、子类或自定义对象，快速尝试不调用任何自定义 hook；先释放部分复制和异常栈，再对原根对象完整调用标准 deepcopy。显式传入 memo 也由标准 deepcopy 处理。这保留自定义键/值求值顺序、memo 别名和原对象生命周期，不改变缓存、训练回放、工作区与历史冻结语义。

含扩展类型的图可能先有少量无用复制再回退；不宣称所有缓存都加速。实际报告热缓存的 tuple 直接回退。`period_report._fast_json_compatible` 仍只检查原有数值解码边界，JSON 错误继续由原序列化路径处理。

## 失败与修正

- r8 复制器在 JSON 数据上正确，但泛化到自定义键值时，与标准 deepcopy 有三项差异：键/值顺序、标量 memo 映射、未保留原容器导致地址复用。反例修前 3 失败/1 通过保存在 `../result-copy-r3/compatibility-before-r9.*`，不以此前全量通过覆盖。
- r9 候选补齐了每个节点的 memo/生命周期行为，但在同一已冻结原 100k 报告的三对交替样本中复制中位数 **3.627→4.038 秒**，更慢，未采用。候选源码及完整样本在 `../result-copy-r9/`。
- 最终 r10 使用整根标准回退。5 项独立隔离/兼容用例通过，包含自定义 hook 释放旧容器并创建新容器时不能错误别名的结果断言。最终全量回归和实际性能另记录在 validation/performance 的 r10 工件。
