# 自有大模型直接回答：四例合成试跑

模型 **deepseek-v4-flash** 能直接组织“观察—可能原因—下一步”，但本轮回答**不能原样作为可靠的产品解释**。主要问题是添加未经来源支持的数字、忽略已知日期、在设备或人群未知时提前解释。能写出合理文字，与来源真实、具体主张获支持，是不同结论。

## 方法与实跑结果

经本轮明确授权，直接调用现有聊天模型；未经过 RAG、网页检索或本地知识库。只发送四份固定合成案例，没有发送私人健康记录，没有改变生产配置或持久联网授权。每例仅调用一次，无重试。

| 案例 | 时延 | 输入 / 输出 token | 完成 |
| --- | ---: | ---: | --- |
| 同设备、同协议，心率 / SDNN / 睡眠共同变化 | 36.092 s | 601 / 1117 | 完整 JSON |
| 睡眠仅 4 晚 / 5 晚记录、完整性未知 | 35.141 s | 474 / 1067 | 完整 JSON |
| 换设备、HRV 定义与年龄未知 | 35.081 s | 522 / 1123 | 完整 JSON |
| 7 天 / 3 天窗口、心率稀疏、睡眠缺失 | 41.548 s | 559 / 1281 | 完整 JSON |

共 **4 / 4 成功**，总时延 147.862 s，总 token 6744（输入 2156、输出 4588）。仅有四个探索案例，不能据此报告生产准确率或 P95。请求、原始文字及解析结果保存在同名 JSON；配置版本本身仍为 service-version-unverified。

## 回答能做到什么

第一例正确保留 60→65 bpm、SDNN 45→36 ms、设备记录睡眠 6.8→5.9 h，并把睡眠、训练、压力等列为候选而非确定个人原因。睡眠例能解释缺失夜选择性造成均值偏移；稀疏例明确反对把缺失当零，以及由单次心率判定持续恶化。四例均没有直接给出疾病诊断或药物、精确训练负荷处方。

## 具体不足

| 案例 | 回答原句 / 问题 | 判断 |
| --- | --- | --- |
| 同口径心率 / 睡眠 | “睡眠不足…表现为…HRV（SDNN）下降”；“<4小时”或“连续…低于6小时” | SDNN 机制概括过强；新增阈值没有逐条来源支持。 |
| 睡眠覆盖未知 | “睡眠时长确实有所增加”；“低于多数成人推荐的7-9小时” | 只知道已记录夜的均值增加，真实时长未知；年龄未知，不能直接用成人标准作判断理由。 |
| 睡眠覆盖未知 | “前期与本期之间的时间间隔…未知” | 输入已经说明连续两个 7 天窗口。 |
| 换设备 / HRV 未知 | 先说“副交感…增强”及“恢复状态改善”，再给设备偏差“10-20 ms”、体位差“3-5 bpm” | 应先拒绝跨设备且未定义 HRV 的生理比较；这些精确范围没有绑定证据。 |
| 换设备 / HRV 未知 | 将“至少5分钟晨起仰卧位”“技术误差（约5-10%）”归于 Plews 论文 | 书目真实也不代表这些具体陈述真实或适用，必须核原文。 |
| 稀疏 / 不等窗口 | “缺少前窗口最后几天（11月5-7日）的心率数据” | 已明确给出 11 月 7 日的 61 bpm，回答前后矛盾。 |
| 稀疏 / 不等窗口 | 把 11 月 11–13 日新记录称为“当前窗口” | 当前窗口已固定为 11 月 8–10 日，新记录只能用于后续观察。 |
| 稀疏 / 不等窗口 | 用“3-5 bpm”解释“5-7 bpm”差值属正常；睡前填写估计睡眠时长 | 正常性范围无支持且数值不覆盖；实际睡眠时长应在醒后记录，不能混入计划值。 |

另一位 Codex agent 只读复核也发现以上主要问题；这不是外部专家评审或临床验证。更多原句及严重程度见 [evaluation.json](evaluation.json)。

## 来源与后续判断

模型给出的 12 个引用条目涉及 9 个独立来源，原始响应全部保留“待核验参考建议”。另行通过 PubMed 核实了其中 8 篇期刊论文的题名、期刊、年份及卷页信息；1 个书章的具体信息尚未核实，见[书目核验与范围说明](reference-verification.json)。本次没有完成全文逐主张审核，因此这些来源没有获得新的产品解释权限。**书目真实**不能证明**文章支持本次解释与具体数值**。

例如 Plews 2013 的摘要明确提醒，精英运动员 HRV 的上升、下降与训练适应并非单一方向，不能直接支持未知人群的恢复改善判断。本地已有相关资料及真正的检索缺项见[证据缺口诊断](../../../docs/product_redesign/evidence_gap_diagnosis.md)。

本轮证明模型具备解释文字的能力，还不能证明当前缺口需要先大量扩充资料。更直接的下一步是修好实际协议 / 人群上下文传递，用确定性事实锁定数字和窗口，再把候选机制逐条绑定已核对来源。缺失哪项主张的证据，再补对应资料。35–42 秒真实时延也说明解释必须异步、状态可见。
